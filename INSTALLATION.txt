VERSION 4 — PARCOURS SCIENTIFIQUE DE PRESENTATION

1. Arrêter l'application et sauvegarder le projet actuel.
2. Copier ENSEMBLE les dossiers core et pages de cette archive à la racine
   du projet existant. Fusionner les dossiers, remplacer les fichiers homonymes.
   Ne pas supprimer les autres modules du projet.
3. Vérifier que core/presentation_v4/dashboard.py existe bien.
4. Dans le dossier du projet : python verifier_installation_v4.py
5. Relancer : python -m streamlit run app.py

SUR STREAMLIT CLOUD
Envoyer dans le même commit les cinq pages, core/datahub.py et tout le dossier
core/presentation_v4, puis redémarrer l'application après le déploiement.
Ne pas copier uniquement les fichiers pages : ils ont besoin du dossier complet.
Une ancienne restriction CPU de la plateforme reste indépendante de cette livraison.

CONTENU ET FONCTIONS
Sources : formats historiques CSV/Excel, aperçu, contrôles, export des intervalles,
édition de la fin documentée de la période d'observation.
Indicateurs : synthèse, diagnostics, modèles, courbes, validation dans cinq onglets.
Optimisation : paramètres regroupés, indicateurs et courbes interactives.
Maintenance : échéance, priorité humaine justifiée, fiche enregistrée en session
et exportable en JSON. Aucun score automatique arbitraire.
Résultats : rapport visuel, tableaux détaillés, CSV/JSON, PDF et Excel.
Le PDF est une synthèse tabulaire ; les graphiques sont dans le rapport visuel.
Les séries numériques des courbes sont incluses dans les exports.

DEPENDANCES
Les dépendances du requirements.txt d'origine couvrent ce parcours :
streamlit, numpy, pandas, scipy, plotly, openpyxl et reportlab.
L'authentification, le thème, l'accueil et les modules 6 à 9 d'origine sont conservés.
Les pages V4 n'importent plus core/scientific_ui.py ni core/workflow.py.
Les anciens fichiers peuvent rester sans être appelés par les cinq pages V4.

VALIDATION EFFECTUEE
Test Streamlit AppTest avec vrais core/ui.py, core/security/auth.py et app.py.
Session authentifiée injectée pour les tests ; formulaire de connexion non modifié.
Navigation réelle entre les cinq pages, import CSV historique Funa par le lecteur,
comparaison des modèles, scénario PLP : horizon à 80 % = environ 1813,4 h.
Huit graphiques interactifs présents dans Indicateurs.
Optimisation, proposition de maintenance, génération PDF et Excel,
retour à Indicateurs sans perte d'analyse : aucune exception dans ce parcours.
Première page du PDF rendue et inspectée.
Ces tests ne garantissent pas tous les fichiers ni toutes les versions du cloud.

UTILISATION
Réimporter l'historique, cliquer Utiliser ces données ; ouvrir Indicateurs,
Calculer l'analyse ; ouvrir Optimisation et Calculer les horizons.
Les résultats sont conservés pendant la session. Télécharger les rapports avant
une déconnexion ou un redémarrage.
Bootstrap et validation prédictive sont disponibles mais exigent d'autoriser
explicitement le calcul coûteux. Ils ne démarrent jamais automatiquement.
L'AICc ne prouve pas l'adéquation ; le modèle choisi peut rester exploratoire.
L'économie des renouvellements/GRP n'est pas implémentée : horizon fiabiliste seul.
